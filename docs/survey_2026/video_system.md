# 视频处理/流媒体/实时渲染中的推理加速与计算复用（2020–2026）
## ——面向「单张图像超分加速框架」的系统级与时空复用思路调研

> 调研目标：梳理视频神经增强系统、压缩域信息复用、实时渲染时空复用、编码器 skip/继承机制、云边协同卸载五大方向，逐项回答：**实测加速幅度与设备、质量保证机制、能否迁移到单图 SR（空间/尺度/通道维度）**。所有条目均经网络检索核验；无法核实的细节标注 [未核验]。

## 1. 视频流神经增强系统

### 1.1 NEMO (MobiCom 2020)
- **文献**：Yeo et al., "NEMO: Enabling Neural-enhanced Video Streaming on Commodity Mobile Devices." KAIST。已核验（sigmobile 程序页 + KAIST pure + PDF）。
- **机制**：只对少量 **anchor frame** 跑 SR DNN；非 anchor 帧在**高分辨率空间**用码流的 motion vector warp + 残差叠加，把 anchor 的 SR 结果"传播"出去。关键创新是**离线逐视频的 anchor 选择算法**：模拟传播误差累积，在质量约束下最小化 anchor 数量。
- **实测**：商用 Android 手机（含高通骁龙旗舰机型，具体型号如 Galaxy Note10/Xiaomi Mi9 [未核验]）。相对逐帧 SR：吞吐 **11.5×**，能耗 **-88.6%**，设备温度可接受。
- **质量保证**：**显式**——anchor 选择以"与逐帧 SR 的质量差 ≤ 阈值"为约束（质量-成本曲线上取点），是本清单里质量保证最正式的系统之一。
- **迁移到单图 SR**：anchor frame → **anchor patch**。时间传播（MV warp）→ 空间传播：对代表性 patch 跑重网络，相似 patch 通过"空间对应关系"（块匹配/自相似性，类似经典 self-similarity SR）复用其特征或输出。NEMO 的核心教益是：**复用需要一个廉价的对应关系来源**（视频里是免费的 MV；单图里需要廉价的 patch 相似度/匹配器）以及**误差累积的显式建模**（单图中对应"路由错误的质量损失上界"）。

### 1.2 Palantír (MMSys 2025)
- **文献**：Jin et al., "Palantir: Towards Efficient Super Resolution for Ultra-high-definition Live Streaming." arXiv:2408.06152。已核验。
- **机制**：把 NEMO 的帧级 anchor 细化为 **patch 级 anchor 调度**。用轻量 DAG 建模 patch 间的时空依赖（MV 跨越 patch 边界），在 patch 粒度决定"跑 SR / 复用传播"。为直播场景设计了低开销的在线质量估计（不需完整跑 DNN 就能估计传播质量）。
- **实测**：SR DNN 推理开销相对帧级 anchor 基线最高 **-80.1%、平均 -38.4%**；调度本身延迟 <5.7% 端到端预算。测试平台为桌面级 GPU（NVIDIA，具体型号 [未核验]）。
- **质量保证**：显式——依赖 DAG 上估计每个 patch 的传播失真，调度以质量约束为目标。
- **迁移到单图 SR**：**这是与 patch 路由 SR 最同构的工作**。它证明两点可直接借用：(a) 决策粒度从帧→patch 收益巨大（细粒度路由 > 粗粒度路由）；(b) 调度器必须极轻（<6% 预算），否则吃掉收益——单图 patch 路由器的开销预算应对标此数量级。其 DAG 依赖思想可映射为单图中 patch 间的**空间依赖**（共享边界、跨 patch 结构连续性）：路由决策不应完全独立，相邻 patch 的处理档位差异过大将产生边界伪影。

### 1.3 EVASR (MMSys 2023 → ACM TOMM 2025 期刊版)
- **文献**：Na Li, Zichen Zhu, Sheng Wei, Yao Liu, "EVASR: Edge-Based Salience-Aware Super-Resolution…" ACM TOMM Vol.21 No.9, Art.245, 2025, DOI 10.1145/3711928。已核验。
- **机制**：**显著性驱动的二分路由**：saliency 高的 patch 走 SR 网络，低的走 bicubic，在边缘服务器完成后下发。即"重要性 → 计算档位"的最简形态。
- **实测**：边缘平台上实现实时增强并降低客户端功耗；具体倍数与设备型号需查 PDF 表格 [未核验，PDF: yaoliu-yl.github.io/publications/tomm-evasr.pdf]。
- **质量保证**：隐式——依赖显著性模型近似人眼重要性；无逐 patch 失真上界，赌的是"低显著区域 bicubic 的退化不被感知"。
- **迁移到单图 SR**：直接可用，但要注意其局限：saliency（语义重要性）≠ SR 难度（bicubic 残差大小）。平坦但显著的区域（人脸皮肤）bicubic 就够；不显著但高频的区域（背景纹理）bicubic 会明显糊。单图路由器应组合**难度信号**（梯度/高频能量/bicubic 残差预测）而非仅语义显著性——这是 EVASR 与 ClassSR 系工作的关键区别点。

### 1.4 Supremo (IEEE TMC 2020)
- **文献**：Yi et al., "Supremo: Cloud-Assisted Low-Latency Super-Resolution in Mobile Devices." IEEE TMC。已核验（juheonyi.github.io/files/Supremo.pdf）。
- **机制**：单图/交互场景的云边协同：本地估计每个 patch 的 SR 收益（边缘/纹理丰富度），只把**高收益 patch** 上传云端 SR，其余本地插值；云端只回传 **SR 结果与插值的残差**（稀疏、易压缩）。配合丢包容忍与流水线化。
- **实测**：相对整图上传下载基线：端到端延迟 **4.85×**↓、带宽 **15.23×**↓；同码率下比 JPEG 高 **2.39 dB** PSNR。手机 + 云 GPU 实测。
- **质量保证**：显式的 patch 收益排序（预算内优先处理收益最大的 patch），质量随预算单调可控——**anytime 特性**。
- **迁移到单图 SR**：Supremo 本身就是单图系统，其两个思想可脱离"云"直接内化到本地框架：(a) **patch 收益预测器**（预测 SR 相对 bicubic 的增益）作为路由信号；(b) **残差式输出**——重网络只学/只算「SR − cheap upsample」的残差，天然与「便宜路径打底、贵路径补差」的分层框架契合。

### 1.5 TileSR (INFOCOM 2024)
- **文献**：Chen et al., "TileSR: Accelerate On-Device Super-Resolution with Parallel Offloading in Tile Granularity." INFOCOM 2024, pp.2538-2547, DOI 10.1109/INFOCOM52122.2024.10621208。已核验。
- **机制**：图像切 tile，选 **top-K 最难 tile**，并行卸载到多台协作移动设备；用**多智能体多臂老虎机**在线学习"tile 难度 × 设备算力/网络"的调度。
- **实测**：延迟 **-17.77%~-82.2%**，质量 +2.38%~10.57%（vs. 各基线；多手机协作实测）。
- **质量保证**：难度感知的 top-K 选择（预算约束下最大化质量收益），bandit 保证在线调度收敛。
- **迁移到单图 SR**：top-K 难 tile 选择即"预算约束下的 patch 路由"，其 bandit 思路可迁移为**在线自校准路由器**：部署后用真实分布持续修正"难度预测 → 档位分配"映射，而不依赖训练集难度分布。

## 2. 压缩域 / 码流信息复用

### 2.1 CIAF (ECCV 2022)
- **文献**：Zhang et al., "A Codec Information Assisted Framework for Efficient Compressed Video Super-Resolution." ECCV 2022, arXiv:2210.08229。已核验（读取了 arXiv 摘要）。
- **机制**：两条复用：(1) **MV 替代光流**做递归 VSR 的帧间对齐——码流免费自带，精度接近学习光流；(2) **残差图指导像素级跳算**：编码残差≈0 的像素说明编码器已判定其与参考帧冗余，SR 网络对这些像素直接复用上一帧的特征/输出，跳过卷积计算（稀疏卷积实现）。
- **实测**：REDS4、H.264 CRF23 下节省最高 **70% 计算量（FLOPs）且无性能下降**。注意：FLOPs 节省 ≠ 等比 wall-clock 加速（稀疏卷积在 GPU 上的实际加速打折），论文以 FLOPs 为主 [wall-clock 细节未核验]。
- **质量保证**：**结构性保证**——"跳"的判据来自编码器的率失真决策（残差小 ⇒ 内容确实没变），不是学习到的近似，因此"跳错"的风险有编码器 RDO 背书。
- **迁移到单图 SR**：单图没有码流 MV/残差，但有两条映射：
  - **尺度维度**：把「低分辨率图 → bicubic 上采样」视为"参考帧"，把「真实 HR − bicubic」视为"残差"。**预测残差能量低的 patch ⇒ bicubic 即可，跳过重网络**——这正是 CIAF 残差跳算在尺度金字塔上的翻版，且判据同样有明确物理含义（bicubic 可解释的部分不必算）。
  - **输入若是 JPEG/HEIC**：DCT 系数分布（高频系数稀疏度）是免费的难度信号，可零成本驱动 patch 路由——单图版的"压缩域信息复用"，工程上被普遍忽视但完全可行。

### 2.2 CDA-VSR (CVPR 2026)
- **文献**：Wang et al., "Compressed-Domain-Aware Online Video Super-Resolution." CVPR 2026, arXiv:2603.07694，代码 yuhangwang-ai/CDA-VSR。存在性已核验（CVF open access + arXiv）。
- **机制**：在线（单向递归）VSR 同时利用 **motion vector、残差图、帧类型（I/P/B）** 三类压缩域信息改善质量-效率折中。帧类型用于调制传播策略（I 帧重算、P/B 帧多复用）[具体模块设计未核验]。
- **实测/质量**：论文报告了效率-质量优于在线 VSR 基线；具体加速倍数与设备 [未核验]。
- **迁移到单图 SR**：「帧类型 → 处理策略」的映射思想值得借鉴：单图中可定义 **patch 类型学**（平坦/边缘/纹理/复杂结构），每类绑定不同的复用/计算策略，而不是单一连续难度分数——离散类型 + 类型专属路径比纯回归难度更可解释、更易做质量保证。

### 2.3 相关背景（简要）
- **COMISR (ICCV 2021, Google)**：压缩感知 VSR，处理压缩伪影，质量向而非加速向；说明压缩域信息也可用于"知道哪里被压坏了"。
- **FAST (MIT, 2017)**：CIAF 的先驱——把 SR 结果沿码流 MV 传播，15× 加速 [属 2021 前，仅作谱系锚点]。
- **AccDecoder (INFOCOM 2023, arXiv:2301.08664)**：复用码流参考关系加速视频**分析** DNN，延迟 -20~80%；证明该思路对任意视频 DNN 通用。

## 3. 实时渲染的时空复用

### 3.1 时域超采样：DLSS SR / FSR2 / TAAU
- **机制**（三者同一管线族，Epic 文档明确说明）：低分辨率渲染 + 每帧亚像素抖动（jitter）→ 用引擎**运动向量**把历史帧重投影到当前帧 → 累积多帧样本重建高分辨率。等于**把超采样的成本摊销到时间轴上**：每帧只算 1 个样本/像素，但有效样本数随历史累积到 4~16+。DLSS 用 AI（现为 transformer 模型，Tensor Core）决定历史融合权重；FSR2/TAAU 用手工启发式（neighborhood clamp 等）。
- **实测**：渲染分辨率降至 1/4（Performance 档），像素着色成本约降 4×，整帧 FPS 提升普遍 1.5~2×+（受非像素瓶颈稀释）；来源为厂商与大量第三方评测，属于**工业级大规模真实部署**，可信度最高。
- **质量保证**：**历史无效化（history rejection/rectification）**是灵魂——disocclusion 检测、深度/法线不一致检测、颜色 clamp。复用的默认姿态是"信任历史"，但有一套显式机制检测"历史不可信"时回退到当前帧样本（局部退化为普通上采样）。
- **迁移到单图 SR**：时间轴消失，但"**摊销 + 无效化回退**"范式可映射到尺度维度：金字塔式 coarse-to-fine SR 中，粗尺度结果 = "历史帧"，细尺度只在"粗尺度预测不可信"（高频残差大、结构不一致）的位置追加计算——即**尺度维度的 history rejection**。另一个映射是通道维度：先算低通道数的"廉价预览"，用其不确定度决定哪些 patch 需要全通道重算（类似 early-exit / cascade）。

### 3.2 Frame Generation (DLSS 3/4)
- **机制**：用前后渲染帧 + 光流（RTX40 硬件 OFA / DLSS4 改为 AI 网络）+ 引擎 MV + 深度，**整帧生成**中间帧；DLSS 4 MFG 一次生成最多 3 帧。
- **实测**：官方最高 **4×** 帧率（含 SR 叠加）；RTX 40/50 系。代价：生成帧有伪影风险、增加输入延迟（靠 Reflex 补偿）。
- **质量保证**：较弱——生成帧不进入渲染历史（错误不累积），依赖高基础帧率让单帧伪影转瞬即逝。
- **迁移到单图 SR**：启发有限但有一条：**「生成帧不进历史」= 复用产物不再作为后续复用的源头，切断误差累积链**。单图 patch 复用中同理：由复用/廉价路径产生的 patch 不应再作为其他 patch 的复用参考（只允许一跳复用），可结构性防止质量崩塌——NEMO/Palantír 恰恰因允许多跳传播而必须付出复杂的误差累积建模成本。

### 3.3 VRS 与 Foveated Rendering —— 与超分 patch 路由的对比分析（重点）
- **机制**：D3D12 Tier2 VRS 允许提供 **shading rate map**（每 8×16 tile 一个档位：1×1/2×1/1×2/2×2/4×4…），GPU 对粗档 tile 每 N 个像素只跑一次 pixel shader，结果广播给邻域。Foveated rendering = 用注视点（眼动仪或镜头畸变先验）生成该 map。
- **实测**：收益强依赖瓶颈：pixel-shader bound 场景收益大，NVIDIA 报告 VR 场景相关技术最高 ~50% 提升（VRWorks 材料，场景相关，非普适保证）；几何/带宽 bound 时收益趋零。Quest 等移动 VR 上 FFR 是默认开启的量产技术。
- **质量保证**：(a) 保守分级预设（fovea 1×1 → 外围 2×2）；(b) 感知模型背书——人眼周边视锐度物理性下降，外围粗采样"按定义"不可见；(c) 已知失效模式清单：高频镜面高光、文字、时域闪烁，遇到则局部禁用。

**与超分 patch 路由的异同（逐条）**：

| 维度 | VRS / Foveated | SR patch 路由 |
|---|---|---|
| 重要性信号 | **外生且几乎免费**：注视点/镜头畸变，物理先验，不需看内容 | **内生且要花钱算**：难度取决于图像内容本身，路由器本身有开销 |
| 信号可靠性 | 感知科学背书（视网膜偏心率-视锐度曲线），错误代价有生理学上界 | 学习式难度预测，可能系统性错判（分布外内容），无先验上界 |
| 档位语义 | 采样密度（同一 shader，少算几次），退化方式平滑可预测 | 不同网络/深度（不同函数！），档位间输出风格可能不连续 → **边界伪影是 SR 路由特有问题**，VRS 几乎没有 |
| 粒度 | 硬件固定 tile（8×16 等），map 生成 <0.1ms | patch 大小自由但受网络感受野约束，路由器预算需 <5% 总时（对标 Palantír） |
| 回退机制 | 每帧重新生成 map，错误只存活 1 帧 | 单图一锤定音，错判永久留在输出里 → **需要更保守的路由或校验回补机制** |
| 共同点 | 二者本质都是「重要性 → 计算密度」的空间预算分配；都证明**非均匀计算在感知上近乎免费**；都需要保守偏置（宁可多算不可少算） | 同左 |

**对单图 SR 框架的三条具体启示**：
1. **寻找"外生免费信号"**：VRS 赢在信号免费。单图对应物：JPEG DCT 统计、bicubic 前后差分（一次减法）、下采样自一致性——路由信号应优先选"近零成本"来源，而非再训一个不小的难度网络。
2. **档位应设计成"同族函数的采样密度差"而非"异族网络"**：让贵/贱路径共享骨干（early-exit、通道裁剪、递归次数），像 VRS 一样"同 shader 不同 rate"，可从根上缓解档位边界不连续。
3. **保守偏置 + 失效清单**：学 VRS 列出已知失效模式（文字、规则纹理、莫尔纹）并对这些模式强制走高档，比追求平均最优路由更能保住质量下限。

## 4. 视频编码的「跳过与继承」机制
- **机制**（H.264/HEVC/VVC 标准，非论文）：**skip mode** = 块级零成本继承：不编码残差、MV 由邻块推导（merge），解码端直接复制参考帧对应块。静态背景大量块被 skip，比特开销近零。此外：参考帧列表复用、merge candidate 继承、HEVC 的 CU 级四叉树把"skip 粒度"做成内容自适应。
- **加速/质量**：这是运行了三十年的量产机制。质量由 **RDO（率失真优化）显式决策**：编码器逐块比较"skip 的失真代价 vs. 编码的比特代价"，λ 加权取优——**每一次"跳"都是算过账的**。
- **迁移到单图 SR**：最深刻的启示不是机制而是**决策框架**：编码器从不用"这块看起来简单"这种启发式，而是用统一的 RD 代价函数比较所有模式。单图 patch 路由的理想形态同构于**模式决策**：对每个 patch 在 {bicubic, 轻网络, 重网络} 间做 **失真-计算量（D-C）优化**，λ 控制质量-速度滑杆——这给了框架一个原则性的、可调的、有大量编码器工程经验可抄的决策理论，而不是 ad-hoc 阈值。CU 四叉树也提示：**patch 大小本身应该内容自适应**（平坦区大块跳、复杂区细分），而非均匀网格。

## 5. 云边协同卸载的框架设计
- 代表：**Supremo**（§1.4，patch 选择性上云 + 残差回传）、**TileSR**（§1.5，多设备并行 + bandit 调度）、**EVASR**（边缘侧 SR + 显著性分配）、AccDecoder（边缘视频分析）。
- **共性框架设计**：三层决策——(1) *what*：哪些 patch 值得贵算力（收益预测）；(2) *where*：本地/边缘/云（延迟-带宽-算力联合）；(3) *how much*：预算内 top-K / anytime 排序。质量控制普遍靠"收益排序 + 预算截断"，天然 anytime。
- **迁移到单图 SR**：即使纯本地框架，"云边"结构也可内化为**异构算力层级**（NPU 轻网络 / GPU 重网络 / CPU 插值）：Supremo 的收益排序 + 残差回传、TileSR 的 top-K 预算分配可原样搬到单机异构调度上，得到"预算可调、质量单调"的 anytime 单图 SR。

## 6. 综合：五类「复用」到单图 SR 三个维度的映射矩阵

| 视频/渲染中的复用 | → 空间维度（patch 间） | → 尺度维度（金字塔） | → 通道/深度维度 |
|---|---|---|---|
| anchor frame + MV 传播 (NEMO/Palantír) | anchor patch + 自相似块匹配传播（需廉价匹配器；限一跳防误差累积） | 粗尺度结果作 anchor，细尺度按需精化 | 浅层特征作 anchor，深层按需追加 |
| 残差指导跳算 (CIAF/skip mode) | bicubic 残差预测 ≈0 的 patch 直接跳过重网络（最可直接落地） | 尺度间残差能量低 ⇒ 停止上探（early stop per patch） | 通道贡献低 ⇒ 剪掉（动态通道剪枝） |
| 时域累积 + history rejection (DLSS/FSR2) | — | coarse 结果默认信任，检测"不可信区域"局部重算（尺度版 history rejection） | 低精度预览 + 不确定度触发全量重算（cascade/early-exit） |
| 重要性→计算密度 (VRS/foveated/EVASR) | patch 路由本体；信号要近零成本；档位要同族函数；保守偏置 + 失效清单 | 重要区域多上一层金字塔 | 重要区域用更宽的通道 |
| RDO 模式决策 (codec skip) | patch 级 D-C 优化 + λ 滑杆 + 内容自适应 patch 划分（四叉树） | 尺度选择进入同一 RD 决策空间 | 深度/宽度档位进入同一决策空间 |

**核心结论**：
1. 视频复用的本质是「免费的对应关系（MV）+ 编码器背书的冗余判据（残差）」；单图缺前者，但**后者可用"bicubic 残差/尺度间残差"完美替代**——这是最应优先落地的机制（CIAF 式跳算的尺度维翻版）。
2. Palantír 证明 patch 粒度 > 帧粒度，且调度开销须 <6%；Supremo/TileSR 证明"收益排序 + 预算截断"给出 anytime 质量保证。
3. VRS 给出档位设计准则（同族函数、保守偏置、免费信号）；codec RDO 给出决策理论（统一 D-C 代价 + λ）。二者组合 = 一个有原则、可调、质量下限可控的单图 patch 路由框架蓝图。
